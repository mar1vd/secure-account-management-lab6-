# Secure Account Management — Лабораторна робота №6

Демонстраційний вебзастосунок для безпечного керування обліковими записами на Node.js, Express та SQLite через WebAssembly-бібліотеку `sql.js` (без компіляції нативних модулів).

## Реалізовані функції

1. Реєстрація/вхід, хешування паролів bcrypt, перевірка політики пароля, профіль і вихід.
2. CAPTCHA з арифметичним завданням для реєстрації.
3. Активація облікового запису одноразовим токеном із терміном дії.
4. Захист від перебору паролів: ліміт невдалих входів, тимчасове блокування, журнал подій та інструменти адміністратора.
5. TOTP 2FA з QR-кодом і можливістю ввімкнення/вимкнення в профілі.
6. Google OAuth 2.0 через Passport (працює після налаштування Google credentials).
7. Відновлення пароля через одноразовий токен з терміном дії.

Додатково: рольова модель користувач/адміністратор, Helmet, обмеження частоти запитів. Сесії зберігаються в пам'яті процесу; для навчального локального запуску це достатньо, але для production потрібне окреме надійне сховище сесій.

## Вимоги

- Node.js 20+
- npm

## Запуск на Windows / macOS / Linux

1. Розпакуйте архів і відкрийте папку проєкту в терміналі.
2. Встановіть залежності:

   ```bash
   npm install
   ```

3. Скопіюйте `.env.example` у `.env` і змініть `SESSION_SECRET` та пароль адміністратора. У Windows PowerShell:

   ```powershell
   Copy-Item .env.example .env
   ```

   У macOS/Linux:

   ```bash
   cp .env.example .env
   ```

4. Запустіть застосунок:

   ```bash
   npm start
   ```

5. Відкрийте http://localhost:3000

Під час першого запуску створюється адміністратор із `ADMIN_EMAIL` та `ADMIN_PASSWORD`, якщо ці змінні задані. Після входу можна відкрити `/admin`.

## Email для локальної демонстрації

Якщо SMTP не налаштований, застосунок не надсилає реальні листи: посилання активації/відновлення та коди демонстрації виводяться в консоль сервера. Це зроблено для локального навчального запуску. Для реальної відправки налаштуйте SMTP у `.env`. Не публікуйте SMTP-паролі.

## Налаштування Google OAuth

1. Створіть OAuth Client ID типу Web application у Google Cloud Console.
2. Додайте Authorized redirect URI: `http://localhost:3000/auth/google/callback`.
3. Заповніть `GOOGLE_CLIENT_ID` і `GOOGLE_CLIENT_SECRET` у `.env`.
4. Перезапустіть сервер. Кнопка Google буде працювати, коли задані обидві змінні.

Без OAuth credentials маршрут повідомить, що інтеграція не налаштована.

## Безпека та обмеження навчального прикладу

- CAPTCHA тут — навчальне арифметичне завдання, а не сервіс reCAPTCHA.
- Для production потрібні HTTPS, сильний унікальний `SESSION_SECRET`, SMTP, резервне копіювання БД, політика ротації секретів і перевірка конфігурації.
- Використовуйте унікальні паролі. Не завантажуйте `.env`, базу даних, токени чи персональні дані в GitHub.
- Після першого входу змініть пароль адміністратора; для публічного розгортання використовуйте секрети платформи, а не `.env` у репозиторії.
- Це навчальний проєкт, а не аудитована production-система.
